# Harness, interfaces and hosting for an LLM "librarian" Discord bot (mid-2026)

*Research date: 2026-08-26. For a solo developer, strongest in Rust (existing `jbotci` Lojban toolkit exposes an MCP server), Python/TypeScript acceptable; Discord first; a separately hosted backend; answers must cite a private corpus.*

**Legend:** statements marked **verified** were read from a primary source on the date given; **inference** marks my synthesis. Every dated link was accessed 2026-08-26 unless a publication date is shown.

## TL;DR

- No official Anthropic Rust SDK exists; `rig-core` is the Rust mindshare crate (fast-moving; citations, cache TTL, strict tools, rmcp glue), `genai` the lighter alternative, and a thin `reqwest` client is viable because the retrieval-relevant API surface is small.
- The Anthropic API already has the librarian pieces: `search_result` blocks returned from your own search tool give block-exact citations (GA); caching (0.1x reads), context editing, compaction, task budgets and effort control cost; Batch (50% off) handles offline indexing.
- MCP is a Linux Foundation project on a stateless 2026-07-28 spec; `rmcp` is the official Tier-1 Rust SDK. Keep `jbotci` on MCP, implement the bot's own corpus tools in-process, and cap tool results at ~10–25K tokens either way.
- Discord: mention/DM-driven gateway bot, auto-threads, a <3 s placeholder, ≤1 Hz progress edits, 2,000-char chunks with masked-link citations; Message Content intent needs verification only above 10K users (since 2026-06-10).
- Host on a ~€6 Hetzner box with SQLite; Cloudflare only suits a slash-command-only variant; Managed Agents can replace the agent backend (not the bot) at $0.08 per active hour plus tokens, but is beta and positioned for async work. Expect ≈$0.15–0.40 per research question on Sonnet 5 with good caching.

## 1. Agent harness choices

### 1a. Hand-rolled tool loop on the Messages API (Rust)

**Verified:** official client SDKs exist for Python, TypeScript, C#, Go, Java, PHP and Ruby plus the `ant` CLI; Rust is not on the list ([CLI, SDKs, and libraries](https://platform.claude.com/docs/en/cli-sdks-libraries/overview)). A Rust harness therefore means a community crate (section 1e) or a thin `reqwest` client against `POST /v1/messages`, whose retrieval-relevant surface is small (`tools`, `system`, `messages`, `cache_control`, `output_config`, SSE).

The loop is not the hard part; what matters is wiring the retrieval features in section 2 (cache breakpoints, `search_result` citations, task budgets, compaction) and streaming, since a multi-minute turn will otherwise hit the 10-minute SDK/HTTP timeout ([Python SDK docs](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/python)). A hand-rolled Rust loop gives full control at the price of re-implementing the official SDKs' beta helpers.

### 1b. Anthropic SDK Tool Runner

**Verified:** the official SDKs include a beta tool runner (`client.beta.messages.tool_runner` + `@beta_tool` in Python; `toolRunner` + `betaZodTool` in TypeScript; equivalents in Go/Java/Ruby/C#/PHP) that derives schemas from function signatures and loops request -> execute -> resend until the model stops; iterate it per message or call `until_done()` ([Python SDK docs](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/python)). It accepts the memory-tool helper (`BetaLocalFilesystemMemoryTool`) as a tool ([memory tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)). No built-in tools, no sandbox: a thin helper you host. Natural choice for a Python/TS backend with your own tools; **not available in Rust**.

### 1c. Claude Agent SDK (Python/TypeScript)

**Verified facts** (from [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview), [Python reference](https://code.claude.com/docs/en/agent-sdk/python), and [Hosting the Agent SDK](https://code.claude.com/docs/en/agent-sdk/hosting), all accessed 2026-08-26):

- It is Claude Code packaged as a library, Python and TypeScript only. Each `query()`/`ClaudeSDKClient` spawns a bundled native `claude` CLI subprocess and talks JSON over stdio; other languages can drive the same loop by running `claude -p ... --output-format json` as a subprocess.
- Built-in tools: Read, Write, Edit, Bash, Glob, Grep, WebSearch, WebFetch. You restrict them with `allowed_tools=["Read","Grep","Glob"]` and `permission_mode="dontAsk"`, point at a corpus with `cwd` and `add_dirs`, and disable filesystem settings with `setting_sources=[]`.
- Custom tools: in-process via `@tool` + `create_sdk_mcp_server(...)`, or external MCP servers (`stdio`/`http`), so `jbotci` plugs in unchanged. API-key auth only; no "Claude Code" branding; renamed from "Claude Code SDK" in September 2025 to signal non-coding use ([Helply, 2026](https://helply.com/blog/create-ai-agent-using-claude-agent-sdk)).
- Subagents via `AgentDefinition(description, prompt, tools, maxTurns, model="haiku")`; sessions resume/fork; partial-message streaming; `ResultMessage.total_cost_usd`; `max_turns`, `max_budget_usd`.
- Hosting: 1 GiB RAM / 1 CPU per agent as a floor, one subprocess per session; transcripts in `~/.claude/projects/` unless you configure a `SessionStore` (S3/Redis/Postgres adapters); the docs list "a chat bot that handles continuous traffic from a platform like Slack" as the long-running pattern; OTEL via env vars; token cost "typically dominates container infrastructure cost by an order of magnitude".

**Is there a "headless librarian over a filesystem corpus" pattern?** Yes: it is Claude Code's native mode (Grep/Glob/Read over a directory plus `CLAUDE.md` memory), and 2026 write-ups list research/knowledge/support agents as supported shapes ([hidekazu-konishi.com](https://hidekazu-konishi.com/entry/claude_agent_sdk_complete_guide.html)). **Inference:** the built-ins already cover "grep + read"; you add semantic search, `jbotci` and citation formatting as MCP tools, and accept Claude Code's opinionated prompt, a per-session subprocess, and a harness you steer rather than own.

### 1d. Anthropic Managed Agents (beta)

**Verified** ([overview](https://platform.claude.com/docs/en/managed-agents/overview), [sessions](https://platform.claude.com/docs/en/managed-agents/sessions), [pricing](https://platform.claude.com/docs/en/about-claude/pricing), [release notes](https://platform.claude.com/docs/en/release-notes/overview), accessed 2026-08-26):

- Public beta since 2026-04-08. A versioned **Agent** (model, prompt, tools, MCP servers, skills) + an **Environment** (Anthropic cloud sandbox, or since 2026-05-19 a **self-hosted sandbox** where your own worker long-polls Anthropic and runs bash/file tools on your box, outbound-only) + **Sessions** streaming SSE events; sandbox provisioning starts at session creation.
- Built-in bash, read/write/edit/glob/grep, web search/fetch, up to 20 MCP servers (auth via **vaults**); tool outputs >100K chars are spilled to a file with a truncated preview (2026-05-19).
- **Memory stores** (beta 2026-04-23): versioned text files mounted at `/mnt/memory/<name>/`, max 8 per session, read-only or read-write; **scheduled deployments** (2026-06-09); hard-dollar **session budgets** (2026-08-07, pauses with `stop_reason: budget_reached`); multiagent rosters.
- **Pricing:** tokens at list rates (caching applies, batch discount does not) plus **$0.08 per session-hour while `running`**; idle is free. Worked example: a one-hour Opus 5 session with 50K in / 15K out is $0.705.

**Fit for a Discord librarian — inference, with reasons:**
- Pros: no loop/sandbox/caching plumbing; a session maps 1:1 onto a Discord thread; memory stores give cross-thread notes; self-hosted sandboxes keep `jbotci` and the corpus on your machine; budgets give a hard per-conversation cap.
- Cons: Anthropic positions it for "long-running tasks and asynchronous work" versus the Messages API for "custom agent loops and fine-grained control" ([overview](https://platform.claude.com/docs/en/managed-agents/overview)); a May 2026 write-up calls it "not for chatbots, not for one-shot prompts" ([Marc Bara, 2026-05-08](https://medium.com/@marc.bara.iniesta/anthropic-just-updated-managed-agents-here-is-what-that-actually-means-for-your-business-de604ecf5a7e)). No published time-to-first-token numbers (unverified latency). The SSE stream has no replay, so the Discord bridge must reconnect-and-dedupe ([events docs](https://platform.claude.com/docs/en/managed-agents/events-and-streaming)). Still beta.
- Net: fewest moving parts if you tolerate beta churn; unattractive if you want to own the loop in Rust.

## 2. Anthropic API features that matter for a retrieval agent

All items below verified against platform.claude.com docs and the [release notes](https://platform.claude.com/docs/en/release-notes/overview) on 2026-08-26 unless marked.

| Feature | Current name / status | Why it matters here |
|---|---|---|
| **Prompt caching** | GA. 5-min write 1.25x, 1-hour write 2x, read 0.1x; max 4 breakpoints; automatic top-level `cache_control` since 2026-02-19; 1-hour TTL GA since 2025-08-13. Minimum cacheable prefix **512 tokens on Opus 5, 1,024 on Sonnet 5, 4,096 on Haiku 4.5** ([prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). | Cache system prompt + tool schemas + corpus map. 5-min breaks even after one read, 1-hour after two; use 1-hour (or a `max_tokens: 0` pre-warm) for bursty Discord traffic. Caches are model-scoped: keep the orchestrator on one model. |
| **Server-side compaction** | Beta `compact-2026-01-12` (2026-02-05); summarizes server-side near a threshold (default 150K). Append the full `response.content` back, not just text. | Long research threads without writing a summarizer. |
| **Context editing** | Beta `context-management-2025-06-27`; `clear_tool_uses_20250919` (2025-09-29), `clear_thinking_20251015` (2025-10-28). | Drops stale grep/read outputs; cheaper and more predictable than compaction for tool-heavy loops. |

Claude scripts calls to your tools inside the code-execution container; only the script's output enters context. | **Citations** | GA, no beta header. (1) `document` blocks with `citations.enabled` (plain text sentence-chunked; "custom content" cites at your block granularity); (2) **`search_result` blocks inside a `tool_result`** from your own tool, each with `source`, `title`, `content[]`; answers carry `search_result_location` citations with `start_block_index`/`end_block_index` and `cited_text` (not billed as output). Also relevant: **effort** (GA 2026-02-05; `low`/`medium` for triage and subagents, `high` for the orchestrator); **tool search** (beta since 2025-11-24, `defer_loading: true`, recommended only at 10+ tools, [docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)); Files API GA 2026-08-19; structured outputs GA 2026-01-29 (for the triage call, not for cited answers); `role: "system"` messages inside `messages[]` on Opus 4.8/Opus 5 (2026-05-28) inject per-thread context without breaking the cache; web search ($10 per 1,000) and free web fetch as an optional fallback to lojban.org; the Usage & Cost Admin API (2025-08-18) reports spend per API key.

**Model choice patterns (mid-2026).** List prices: Opus 5 $5/$25, Sonnet 5 $2/$10 (introductory price made permanent 2026-08-10), Haiku 4.5 $1/$5, Fable 5 $10/$50 per MTok ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Anthropic's guidance is Haiku for simple tasks, Sonnet for most production work, Opus for the hardest reasoning (same page), with reading-heavy sub-tasks delegated to a cheaper worker such as Haiku 4.5 in the Managed Agents multiagent docs; the Claude Code team's [June 2026 post](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code) suggests a classifier agent that picks the model per task. **Inference for this project:** Sonnet 5 orchestrator at `effort: high` with citations, Haiku 4.5 for triage and parallel read-and-extract subagents, Opus 5 behind an explicit flag. Haiku 4.5's 4,096-token cache minimum means a short Haiku triage prompt will not cache.

## 3. MCP in 2026

**Spec and governance (verified).**
- Revisions: 2025-06-18 -> [2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/changelog) (OIDC discovery, URL-mode elicitation, experimental Tasks) -> **[2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)**, the current spec.
- 2026-07-28 is a **stateless rewrite** ([breaking-change list](https://stacktr.ee/blog/mcp-2026-spec-changes)): sessions and the `initialize` handshake are gone (per-request `_meta` + `server/discover`); server-initiated sampling/elicitation become multi-round-trip requests; **Tasks moved to an extension** (poll-based); `tools/list` carries `ttlMs`/`cacheScope`; OAuth hardened, DCR deprecated for CIMD; legacy HTTP+SSE and Roots/Sampling/Logging deprecated with a 12-month window.
- MCP moved to the Linux Foundation's Agentic AI Foundation on 2025-12-09 ([LF](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)); the [2026-08-22 roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/) prioritises "standardizing tool result handling and progressive tool discovery"; the [registry](https://modelcontextprotocol.io/registry/about) is still preview and not for private servers.

**Rust SDK (verified).** [`rmcp`](https://github.com/modelcontextprotocol/rust-sdk) is the official SDK: 3.1.4 (2026-08-20), 22.2M downloads, promoted to **Tier 1 on 2026-08-21** with full conformance ([summary](https://www.digitalapplied.com/blog/mcp-sdk-conformance-tiers-what-tier-1-means)). It implements 2026-07-28 while staying compatible with 2025-11-25; features cover stdio server/client, a Streamable HTTP server as a Tower service (mounts in Axum), a reqwest client, OAuth 2.1 client with PKCE (server side only RFC 9728 metadata), elicitation, `#[tool]` macros and the Tasks extension ([OAuth doc](https://github.com/modelcontextprotocol/rust-sdk/blob/main/docs/OAUTH_SUPPORT.md)). `rust-mcp-sdk` is alive but niche; `mcp-sdk`/`mcp-core` are dead; Rig ships `rig-rmcp`. Keep `jbotci` on rmcp 3.x.

**MCP as the seam between librarian and corpus tools.** Prefect's 2026-04-14 framing is the consensus: function calling when a tool is "tightly coupled to a specific application", MCP when tools "need to be shared, discovered, or governed independently" ([MCP vs function calling](https://www.prefect.io/resources/mcp-vs-function-calling)). On result size, every source agrees:
- Anthropic, [Writing tools for agents (2025-09-11)](https://www.anthropic.com/engineering/writing-tools-for-agents): pagination, filtering and truncation with sensible defaults; a `response_format: concise|detailed` switch (concise used about a third of the tokens); namespace and consolidate tools.
- Anthropic, [Code execution with MCP (2025-11-04)](https://www.anthropic.com/engineering/code-execution-with-mcp) and Cloudflare's [Code Mode (2025-09-26)](https://blog.cloudflare.com/code-mode/): definitions and intermediate results are the two costs; letting the model write code against a tool API cut 150K tokens to 2K in Anthropic's example.
- Claude Code warns at 10K tokens of MCP output and **hard-caps at 25K** (`MAX_MCP_OUTPUT_TOKENS`), overridable via the `anthropic/maxResultSizeChars` annotation ([Claude Code MCP docs](https://code.claude.com/docs/en/mcp)); Managed Agents spills >100K chars to a file.
- Latency: no rigorous stdio-vs-HTTP benchmark exists (vendor "20–50 ms" claims lack methodology, [Obot, 2026-02-10](https://obot.ai/resources/learning-center/mcp-vs-function-calling/)). **Inference:** framing cost is milliseconds and dwarfed by model latency; MCP's real cost is tokens, not transport.

**Applied here (inference):** keep `jbotci` on MCP (already shared with Claude Code/Desktop); implement the librarian's grep/semantic-search/reader tools as in-process Rust functions with a hard result budget (10–25K tokens, paginated) and a `concise|detailed` switch; expose them later as an rmcp Streamable HTTP service if you want them inside Claude Code too.

Closest Rust reference: [MrMcEpic/discord-bot-rs](https://github.com/MrMcEpic/discord-bot-rs) (serenity + poise, mention-triggered AI chat with tools).

**Interaction model (verified against Discord docs, accessed 2026-08-26).**
- Interactions must be acknowledged within **3 seconds**; `DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE` shows "thinking..."; the token stays valid **15 minutes** for follow-ups ([Receiving and Responding](https://docs.discord.com/developers/interactions/receiving-and-responding)). Longer jobs must fall back to bot-token messages in the thread.
- Limits: 2,000 chars of content; embed description 4,096; Components V2 text 4,000 chars total, max 40 components, needs the `IS_COMPONENTS_V2` flag which disables `content`/embeds and cannot be removed on edit ([Message resource](https://docs.discord.com/developers/resources/message); [Components](https://docs.discord.com/developers/components/using-message-components)).
- Markdown: headers, `-#` subtext, lists, quotes, fenced code; masked links `[text](url)` render for bots (not for users), tables do not ([Markdown Text 101, updated 2026-08-24](https://gist.github.com/matthewzring/9f7bbfd102003963f9be7dbcf7d40e51)). Set `allowed_mentions` so an LLM-emitted `@everyone` cannot ping. Typing indicator expires after 10 s; post a placeholder and edit it instead.
- Rate limits: Discord documents only the 50 req/s global limit and tells you to honour `X-RateLimit-*` ([Rate Limits](https://docs.discord.com/developers/topics/rate-limits)); "5 messages / 5 s per channel" is community-observed. Real bots stream by editing at ~1 Hz: llmcord uses `EDIT_DELAY_SECONDS = 1` and splits at 4,000/4,096 chars ([llmcord.py](https://github.com/jakobdylanc/llmcord/blob/main/llmcord.py)); OpenClaw offers `partial`/`block`/`progress` modes and splits at 2,000 ([OpenClaw Discord docs](https://docs.openclaw.ai/channels/discord)).
- Threads: "Start Thread from Message" yields a thread whose ID equals the source message ID (a free session key), one thread per message, `auto_archive_duration` 60–10,080 min ([Channel resource](https://docs.discord.com/developers/resources/channel)); llmcord and [zebbern/claude-code-discord](https://github.com/zebbern/claude-code-discord) (Agent SDK, thread-per-session with permission buttons, pushed 2026-08-01) both use this.

**Message Content intent.** Without it a bot still gets content for DMs, @-mentions and its own messages ([privileged intents](https://docs.discord.com/developers/events/gateway#privileged-intents)), so a mention/DM librarian needs no privileged intent. The verification threshold changed on **2026-06-10** from "100+ servers" to ">10,000 unique users" with a 90-day window ([Privileged Intent Review](https://docs.discord.com/developers/gateway/getting-started-with-privileged-intent-review)). Caveat: in-thread follow-ups that do not mention the bot arrive without content unless you have the intent or the user replies to the bot. For a private bot on a few servers, just enable it.

**Memory, gating, long jobs.** llmcord rebuilds history from the reply chain (max 25 messages, no database) and gates by user/role/channel ID; Anthropic's official Discord channel plugin bootstraps an allowlist by DM pairing code and requires the Message Content intent ([plugin](https://github.com/anthropics/claude-plugins-official/tree/main/external_plugins/discord)). Recommended long-job flow (inference): ack < 3 s with a placeholder -> edit it at <= 1 Hz with progress -> final answer as a new message with 👍/👎 and a Cancel button whose `custom_id` carries the job ID -> per-guild concurrency cap.

**Gateway vs HTTP interactions.** Two mutually exclusive modes: gateway WebSocket, or an Interactions Endpoint URL receiving Ed25519-signed POSTs ([Interactions overview](https://docs.discord.com/developers/interactions/overview)). HTTP-only apps get interactions only, never `MESSAGE_CREATE` (no @mention/DM chat), but can still use the bot token for REST and the webhook for 15 minutes ([discord/cloudflare-sample-app](https://github.com/discord/cloudflare-sample-app)). Cloudflare Durable Objects: section 6.


## 5. Conversation and memory state

**Vendor "memory layers" (verified, accessed 2026-08-26).**
- **Mem0**: Apache-2.0 OSS plus hosted tiers ([pricing](https://mem0.ai/pricing)); its own 2026-08-26 report admits production adoption is "more measured" than projected ([blog](https://mem0.ai/blog/state-of-ai-agent-memory-2026)). **Letta (ex-MemGPT)** pivoted on 2026-03-16 to a git-backed coding harness, sunsetting its server-side memory tools ([Our Next Phase](https://www.letta.com/blog/our-next-phase/)).
- **Anthropic memory tool** (section 2) and **Managed Agents memory stores** (2,000 memories/store, 100 KB each, versioned; the docs warn that prompt injection into a `read_write` store poisons later sessions) ([memory docs](https://platform.claude.com/docs/en/managed-agents/memory)).
- **Inference:** Zep (OSS discontinued 2025-04) and the others have not become standard for a single-corpus bot; Anthropic's guidance converges on *files the agent reads and writes*.

**Patterns that matter for a librarian.** Anthropic's [Effective context engineering (2025-09-29)](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) names compaction, structured note-taking (`NOTES.md` / memory tool) and subagents returning 1–2K-token summaries; [Effective harnesses for long-running agents (2025-11-26)](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) adds the progress-log pattern; Claude Code's auto-memory is a concrete instance (a `MEMORY.md` index, first 200 lines loaded per session, plus topic files) ([memory docs](https://code.claude.com/docs/en/memory)). Transposed:

- **Per-thread transcript** in SQLite/Postgres keyed by Discord thread ID, replayed as `messages[]` (with compaction or context editing once long); plus a small **per-user file** (preferences, expertise) under `/memories/users/<id>.md` via the memory tool.
- **A verified-answers store**: when a human reacts with a checkmark, write `question / answer / citations` to `/memories/verified/` and let a search tool surface it first. *Automatic* semantic caches show 15–40% hit rates but 1–7% false positives at 0.93–0.95 similarity; the advice is exact-match first, provider caching second, semantic cache only with a sampled eval loop ([respan.ai, 2026-05-25](https://www.respan.ai/articles/semantic-cache-llm)); Redis LangCache is still preview. **Inference:** a curated store the agent searches is lower-risk than an automatic short-circuit. Notes the librarian writes back into the corpus (`notes/<topic>.md` with provenance) are the highest-leverage form because the same tools can grep them; keep them in a separate directory so canonical sources and own notes stay distinguishable when citing.

## 6. Hosting

The two hard constraints are (a) a **long-lived Discord gateway WebSocket** (unless you go slash-command-only over HTTP interactions) and (b) **multi-minute research jobs**.

**Small VPS (verified prices).** Hetzner CX23 (2 vCPU / 4 GB) €5.49/mo + €0.50 IPv4 after the 2026-06-15 adjustment ([Hetzner](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/)); Fly.io shared-cpu-1x 1 GB ≈ $5.92/mo but autostop only watches *inbound* traffic, so set `auto_stop_machines = "off"` ([autostop](https://fly.io/docs/launch/autostop-autostart/)); Railway Hobby $5 + usage ([plans](https://docs.railway.com/pricing/plans)); Render $7; DigitalOcean $6. **Inference:** a ~€6 Hetzner box running one Rust binary + SQLite + the corpus is cheapest and simplest, keeps `jbotci` local, and can also host an Agent SDK process or a self-hosted Managed Agents worker.

**Cloudflare (relevant because you already have the plugin).**
- Durable Objects *can* hold an outbound WebSocket since 2026-06-19, but it keeps the DO alive only **15 minutes per connection** and outgoing sockets never hibernate ([changelog](https://developers.cloudflare.com/changelog/post/2026-06-19-outbound-connections-keep-dos-alive/)); [discord-gateway-cloudflare-do](https://github.com/dcartertwo/discord-gateway-cloudflare-do) works around it with alarms + resume.
- Workers Paid is $5/mo and Workflows steps have unlimited wall-clock ([pricing](https://developers.cloudflare.com/workers/platform/pricing/)); **Containers** went GA 2026-04-13 but hosts restart on an irregular cadence and platform events can stop an instance even if kept awake ([FAQ](https://developers.cloudflare.com/containers/faq/)); a 1 GiB container kept awake ≈ $6–8/mo, VPS money without VPS guarantees.
- **AutoRAG is now "AI Search"** (renamed 2025-09; hybrid BM25 + vector; free in open beta) ([docs](https://developers.cloudflare.com/ai-search/)); Vectorize $0.01 per million queried dimensions.
- **Inference:** Cloudflare fits a *slash-command-only* bot (interactions -> Worker -> Workflow -> follow-up within 15 minutes) with AI Search as the index; it is a poor fit for a mention/DM bot that must hold the gateway, and `jbotci` would still need a host elsewhere.

**Anthropic Managed Agents as the host.** No fixed cost; $0.08 per session-hour while running plus tokens; sessions persist server-side; webhooks and scheduled deployments exist ([webhooks](https://platform.claude.com/docs/en/managed-agents/webhooks)). Something must still hold the Discord gateway, so this replaces the agent backend, not the bot process; 300 two-minute questions a month ≈ $0.80 of runtime.

**Monthly fixed-cost ranges (inference):** VPS €6–12; Railway/Render $5–25; Cloudflare $5–15; Managed Agents ≈ $0 fixed + $0.08 per active hour. Tokens will exceed all of these once usage is non-trivial.

## 7. Cost control and observability

- **Per-user rate limits and budgets.** Token bucket per Discord user plus a monthly per-guild cap ([agentgateway](https://agentgateway.dev/docs/standalone/latest/llm/cost-controls/budget-limits/)); one Anthropic API key per guild lets the Usage & Cost Admin API attribute spend per key ([docs](https://platform.claude.com/docs/en/manage-claude/usage-cost-api); requires an org account).
- **Per-query budgets.** `task_budget` is advisory and Opus-class only ([docs](https://platform.claude.com/docs/en/build-with-claude/task-budgets)); pair it with `max_tokens`, a tool-call counter and a wall-clock deadline. Managed Agents session budgets are the hard-dollar version; the Agent SDK has `max_turns` and `max_budget_usd`. Caching the corpus prefix under a 1-hour breakpoint remains the single largest lever; verify with `usage.cache_read_input_tokens`.
- **Cheap-model triage** (Haiku classifies lookup / parse / research, then Sonnet or Opus) is claimed to save 40–70% ([builderworld](https://builderworld.io/en/learn/llm-routing-multi-model); [TrueFoundry](https://www.truefoundry.com/blog/llm-routing-cost-quality-aware-model-selection)) — vendor numbers, unverified here. **Answer caching**: section 5.
- **Observability.** Langfuse: MIT self-host (v3 = Postgres + ClickHouse + Redis + S3), cloud free 50K units/mo, acquired by ClickHouse 2026-01-16 with no licence change ([pricing](https://langfuse.com/pricing)); Arize Phoenix (ELv2) is the other self-host option. **OTel GenAI semantic conventions are still not stable** (`gen_ai.*` remains "Development", moved to its own repo in v1.42.0, 2026-06-12) ([analysis, July 2026](https://john-hodge.com/blog/opentelemetry-genai-semantic-conventions/)). The Agent SDK exports OTEL via env vars; in Rust use `tracing` + OTLP.
- **$/query in 2026.** Anthropic's multi-agent research post (2025-06-13): agents use ≈4x the tokens of chat, multi-agent ≈15x ([Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)). Secondary 2026 figures: ≈$2.29 per Artificial Analysis Intelligence-Index task on Sonnet 5 ([CloudZero](https://www.cloudzero.com/blog/claude-pricing/)); "20–50 tool calls per investigation" ([keito.ai](https://keito.ai/blog/ai-research-agent-cost-tracking/)). **Back-of-envelope (inference)**: 30 tool calls, ~150K cumulative input mostly cache-read, ~8K output => Sonnet 5 ≈ $0.15–0.40, Haiku 4.5 ≈ $0.08–0.20, Opus 5 ≈ $0.40–1.00 per question; note the Opus 4.7+/Sonnet 5 tokenizer yields ~30% more tokens ([pricing](https://platform.claude.com/docs/en/about-claude/pricing)).

## Recommendation for this project

**Architecture (both variants).** One always-on process holds the Discord gateway and a queue to the agent backend; per-thread jobs ack in <3 s, post a placeholder, edit progress at ≤1 Hz, and deliver 2,000-char chunks with masked-link citations. Transcripts and memory live in SQLite (Postgres later); the corpus is on the same disk; `jbotci` runs locally over MCP. Sonnet 5 orchestrates at `effort: high`; Haiku 4.5 triages and runs read-and-extract subagents at `effort: low`; Opus 5 sits behind a flag. Cache system prompt + tool schemas + corpus map under a 1-hour breakpoint; return every hit as a `search_result` block; context-edit old tool results; compact only long threads; enforce `max_tokens`, a tool-call cap, a deadline and a per-user token bucket in code.

**Rust-first variant.**
- Bot: serenity 0.12.5 + poise 0.6.2 (stable; V1 buttons are enough), or twilight 0.17 if you want Components V2 from crates.io.
- Harness: hand-rolled loop over `POST /v1/messages` with `reqwest` + SSE, or `rig-core` if you accept its churn (`genai` for caching/thinking helpers without citations). Tools as in-process `async fn`s; `jbotci` via the `rmcp` stdio client; memory tool as six file ops on a per-user directory.
- Hosting: one Hetzner CX23/CAX11 (~€6/mo) running the binary + SQLite + corpus; `tracing` -> OTLP -> self-hosted Langfuse or Phoenix.
- Trade-offs: you own everything (fast to debug, cheap to run), but you re-implement what the SDK helpers give Python/TS for free (tool runner, memory helper, client-side compaction, thinking-block round-tripping) and track a fast-moving beta surface by hand; no Agent SDK or Managed Agents worker exists in Rust, so batteries-included options are off the table in-process (a Managed Agents session can still be driven over REST).

**Python/TypeScript variant.**
- Bot: discord.py 2.7 (or discord.js 14.27); llmcord is the reference for mention handling, reply-chain history and edit streaming.
- Harness, pick one: (a) **Claude Agent SDK** with `allowed_tools=["Read","Grep","Glob"]`, `cwd=corpus`, `setting_sources=[]`, `jbotci` and semantic search as MCP, Haiku subagents, `max_budget_usd`, `SessionStore` on Postgres: grep/read, compaction, subagents and OTEL for free at the cost of one ~1 GiB subprocess per active session. (b) **Official SDK Tool Runner** with your own tools and the memory helper: smaller, fully yours. (c) **Managed Agents** with a self-hosted sandbox worker on your VPS so `jbotci` and the corpus never leave your machine; the Discord process becomes an SSE bridge; memory stores and session budgets come built in; accept beta churn and unverified latency.
- Hosting: same €6 VPS (Agent SDK needs ~1 GiB per concurrent session, so size RAM by expected parallel questions); Fly.io only with `auto_stop_machines = "off"`.
- Trade-offs: fastest path to a working librarian (especially (a)), day-one access to every beta feature, the largest pool of reference bots; but a second runtime beside `jbotci`, and (a)/(c) put the retrieval loop behind a harness you steer rather than write.

**Where Cloudflare fits.** Only for a deliberately slash-command-only bot (Worker for interactions, Workflow for the job, AI Search as index); a mention-driven bot there is possible but fragile, and `jbotci` still needs a host.

**My pick (inference):** start Rust-first with a hand-rolled Messages loop (the part you want to own), serenity + poise, SQLite, `rmcp` to `jbotci`, on a Hetzner box; adopt `rig-core` only if you find yourself re-implementing its citation/cache types. Prototype the Python Agent SDK path in a weekend as a quality benchmark, because its grep/read/subagent loop *is* a librarian and will show quickly whether your own loop is competitive. Revisit Managed Agents when it leaves beta or publishes latency numbers.
