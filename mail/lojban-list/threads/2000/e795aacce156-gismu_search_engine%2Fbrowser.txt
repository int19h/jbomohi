No idea how it is supposed to work under DosEMU, but your lesson result 
should be updated as you do the lesson - in other words, when you get a 
screen at the end of a session saying you have so many words in various 
lessons, that reflects the updated state of your lesson file, which was 
rewritten during the lesson.  When you exit the program, there is a DOS 
file close.  The lesson file will be the username you typed at the start of 
the session to create the lesson, plus the letter L dot FL1, and there 
should be a corresponding human-readable ASCII log file using the letter H.

As far as I recall, these files are rewritten every lesson, so there should 
be no question that they should be updated.  But don't type the wrong user 
name or work in the wrong directory %^).

Being inspired I decided to try a quick proof-of-concept.

It's a java applet that also searches the gismu list. It only searches for
the lojban gismu though and only gives you the rasfi and the english
meaning.

But it should be easy to extend.

The reason I wrote it is because it's probably better to have the whole
dictionary on the client-side to allow faster searches. Of course the
drawback is that you have to wait for the dictionary to be transferred
intially.

Anyway, try it, if anyone asks me to improve it, I will.
