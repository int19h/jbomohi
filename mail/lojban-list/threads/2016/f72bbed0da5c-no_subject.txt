Yes. But also no. I feel like cleaning up the data should come after getting a new jbovlaste thing where people can better input and delete entries and a way to fix the horrible issue of everyone inputting the latex x's differently. I had to write a mean long regex to handle all the different creative ways people have input those latex x's. I don't have a clear vision about /how/ exactly that kind of interface should look and behave so I haven't been working on it.

Definitely I want the way the definitions are internally stored to be split by the x-components. Maybe even this way would allow a dictionary to (more easily) display definitions outside of the cursed x1 selbri xn English order. Maybe a way to add tags to the internal representation of the x's such as 'event' or 'du'u': that would be plixau.

As for the encoding issue, jbovlaste is on github so you have the ability to find the bug yourself if you want. It's good to know that error is there though.
