I noticed what jbofi'e and camxes handle CU differently. For example,
in {mi pu kalte gi'e citka} jbofi'e interpretes {pu} as selbri tag
(and so it is applies only to the first bridi-tail), and camxes
interpretes it as a tag term (and so it applies to the whole
sentence):

jbofi'e: mi (pu kalte) gi'e citka
camxes: (mi pu) (kalte gi'e citka)

jbofi'e with -ie option reconstructs elidable elements as {mi CU pu
kalte VAU gi'e citka VAU VAU}.
camxes seem to interpret the same sentence as {mi pu KU CU kalte VAU
gi'e citka VAU VAU}.

I guess jbofi'e handles the sentence correctly, and so there must be
an error in camxes and/or in PEG grammar used by it. Unfortunately, I
am not able to point it out, but I hope what this report will be of
use.

mi'e la ramcinfo re'i

I think the fix should be trivial, just replace:

term-1 <- sumti / ( !gek (tag / FA-clause free*) (sumti / KU-clause?
free*) ) / termset / NA-clause KU-clause free*

with:

term-1 <- sumti / ( !gek (tag !selbri-1 / FA-clause free*) (sumti /
KU-clause? free*) ) / termset / NA-clause KU-clause free*

I'm pretty sure we have dscussed this one before. If I'm not mistaken,
the current PEG is consistent with the official YACC and BNF.
