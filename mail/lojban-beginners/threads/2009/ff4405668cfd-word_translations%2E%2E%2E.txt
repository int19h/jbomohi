> I was unable to find the following words in the jbovlaste:
> Standard/Official/Established (as in "Standard/official document");
.skamyxatra

{catni} - x1 has authority/is an official in/on/over matter/sphere/persons x2
          derived on basis x3

> Close (as in "Close the file");

{ga'orgau} - from "{ganlo gasnu}," cause to be closed

> Module (as in "Part/A-part-of");

{pagbu} - x1 is a part/component/piece/portion/segment of x2 [where x2 is a
          whole/mass]; x2 is partly x1

> Search/Find (as in "Search for/Find <something>");

{sisku} - x1 seeks/searches/looks for property x2 among set x3 (complete
          specification of set)

{facki} - x1 discovers/finds out x2 (du'u) about subject/object x3; x1 finds
          (fi) x3 (object)

> Output/Result (as in "The output/results of the process")

{te pruce} - x3 is the output/results of input x2 to process x3, passing
	     through steps/stages x4

mu'omi'e .kamymecraijun.

I think that the terms used when talking about files are based in a metaphor of 
a traditional old-style file cabinet, back when files were pieces of paper 
residing in folders, which were probably named so because that was what they 
were: folded pieces of paper.

If we were to keep using this metaphor for talking about files, then the word 
'closing' in the usual sense (closing the folder containing the files and 
thereby no longer being able to edit them) would be completely appropriate.

At least, so it seems to me.

That's part of the issue: the English represents metaphorical use of
the words "file", "folder", "open", "close", etc.  In Lojban, we have
cmavo to represent metaphorical (and/or non-veridigal) usages.  But,
literally, computer files and directories have nothing to do with
paper files or hanging folders.
