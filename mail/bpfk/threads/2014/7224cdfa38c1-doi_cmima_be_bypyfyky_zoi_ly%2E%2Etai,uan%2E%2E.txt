By the way the change in ilmentufa no’u camxes-exp that allows this is quite small:  

camxes.js.peg:
diphthong = expr:(a i / a u / e i / o i) !nucleus !glide {return _join(expr);}
camxes-exp.js.peg:
diphthong = expr:(a i / a u / e i / o i) !nucleus {return _join(expr);}

And as la selpa’i pointed out when this was brought up on IRC, it mainly fixes the issue where strings like “auie” are parsefails in camxes (and jbofi’e) but cmavo clusters {au ie} under camxes-exp.

The reason for not allowing a glide directly after a diphthong was so as to
avoid the very similar sounding "ai,ia" vs "a,ia", "au,ua"vs "a,ua", and so
on.

One option that was considered at the time was to disallow Vi,iV and Vu,uV,
but allow Vi,uV and Vu,iV, but in the end the simpler rule was preferred.

When I made that change to ilmentufa I did consider that too, and in the 
end I also went with the simpler rule, except it was to allow everything 
instead of nothing. I now think that the middle ground would be 
preferable, because camxes currently forbids a lot of easy-to-pronounce 
combinations while ilmentufa allows a few hard-to-distinguish ones.

     diphthong = expr:( ( a u !u / ( (a i / e i / o i ) !i ) ) !nucleus 
) {return _join(expr);}

This allows "taiuan" and "auie", but forbids "aiia" and "auua".
